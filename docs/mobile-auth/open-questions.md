# Открытые вопросы и как их закрыть

Список того, что осталось непроверенным или требует решения. Отсортирован по важности:
сначала то, что блокирует разработку, потом уточнения.

## A. Требуют ответа от вендора/владельца CRM

| # | Вопрос | Зачем | Как получить ответ |
|---|---|---|---|
| A1 | Есть ли официальный мобильный API и документация к `widget_client_mobile/*`? | Возможно, не нужно использовать внутренний протокол | Письмо вендору, [vendor-report.md](vendor-report.md) |
| A2 | Разрешено ли использовать `user/login` и `widget_schedule/*` в стороннем приложении? | Снимает риск блокировки и претензий | Письменное подтверждение |
| A3 | Будут ли чиниться уязвимости S1–S3 (см. [findings.json](findings.json))? | От этого зависит, можно ли вообще полагаться на логин по паролю | Ответ на отчёт |
| A4 | Какие разделы ЛК включены в тариф виджета (оплата, заморозка, запись)? | Определяет объём приложения | Настройки виджета в CRM |
| A5 | Есть ли у тенанта свой домен/брендирование для приложения? | Push, deep links, диплинки на оплату | Владелец CRM |

## B. Клиентский контур (виджет) — технические

| # | Вопрос | Как проверить | Блокирует |
|---|---|---|---|
| B1 | Payload методов `widget_client_lk/branch`, `template`, `product_types`, `account_detail` | Сейчас `500` «про параметры»; подобрать поля по компонентам `clientLk` в JS-бандле | Профиль, шаблоны, товары |
| B2 | Payload `widget_client_mobile/individual`, `teachers`, `waitings`, `notifications` | Аналогично, по чанкам `widgets/clientMobile` | Запись на индивидуальные, тренеры |
| B3 | Семантика `widget_schedule/places` → `{group, self}` | Сравнить с числом мест в группе; понять, где свободные места | Экран записи |
| B4 | Сколько живёт `secret`, меняется ли при смене пароля | Сменить пароль тестовому клиенту, проверить старый `secret` | Долгие сессии, logout |
| B5 | Есть ли лимит попыток на `check_password`/`phone_info` | 10–15 неверных попыток на тестовом клиенте | Антибрутфорс |
| B6 | Поведение при нескольких клиентах на один телефон (`ids` — массив) | Завести второго клиента с тем же номером | Экран выбора профиля |
| B7 | Нужен ли `Referer`/`Origin` | Повторить запросы без `Referer` (сейчас все шли с ним) | Совместимость |
| B8 | Работает ли `widget_client_mobile/*` без `client_id`/`secret` (как `schedule`) | Повторить `summary`/`info` без кредов | Безопасность, кэш |

## C. Сотрудничий контур — технические

| # | Вопрос | Как проверить | Блокирует |
|---|---|---|---|
| C1 | TTL PHP-сессии и семантика `user/refresh_token` | Логин, пауза, `user/current`; вызвать `refresh_token` | Долгие сессии |
| C2 | Принимает ли сервер `Cookie: PHPSESSID=` вместо query | Запрос с заголовком Cookie | Утечка сессии в логи nginx |
| C3 | Отдаёт ли `user/load/{id}` с API-ключом поля `apiToken` и `password` | Запрос с ключом | Вариант с персональными токенами |
| C4 | Лимит попыток на `user/login` | 10–15 неверных на тестовом сотруднике | Антибрутфорс |
| C5 | Рвётся ли сессия при смене пароля в вебе | Сменить пароль тестовому сотруднику | UX |
| C6 | Что возвращает `user/api_example` (нет ли там токена) | Запрос с сессией | Возможный способ получить `apiToken` |
